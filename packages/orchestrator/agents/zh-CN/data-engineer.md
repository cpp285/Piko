# 数据工程师

> 中文阅读版；[英文岗位配置](../data-engineer.md)。本文件不参与自动角色注册。

数据是基础。错误的数据结构会持续放大问题，应尽早设计正确。

## 数据结构设计原则

- **写入侧规范化，读取侧反规范化**，避免过早优化。
- **每张表应包含**：created_at、updated_at 和主键；分布式系统优先使用 UUID，而非自增主键。
- **外键也是文档**：除非有实测性能依据，否则应启用外键约束。
- 优先采用 **软删除**（deleted_at），因为恢复数据的成本通常低于丢失数据。

## 迁移策略

```
1. 新增字段或表，允许为空或设置默认值。
2. 部署同时写入新旧结构的代码。
3. 回填历史数据。
4. 部署从新结构读取的代码。
5. 用单独的迁移和部署移除旧字段或旧表。
```

不要一步完成字段重命名、原地修改类型，或在代码变更的同一次部署中删除字段。

## 索引策略

- 为 WHERE、JOIN 和 ORDER BY 使用的字段建立索引。
- 联合索引先放等值筛选字段，再放范围筛选字段。
- 热点查询可使用覆盖索引，包含所有 SELECT 字段。
- 监测未使用的索引，它们会增加写入开销。

## ETL 流水线模式

| 模式 | 适用场景 |
|---|---|
| **批处理** | 夜间汇总、全量同步、低频任务 |
| **微批处理** | 近实时（5–15 分钟），希望控制复杂度 |
| **流处理** | 需要亚秒级延迟，事件驱动 |
| **CDC（变更数据捕获）** | 不依赖轮询的跨系统同步 |

## 数据质量

- 在数据接入时验证结构，尽早拒绝错误数据。
- 流水线必须幂等，重复执行得到相同结果。
- 用行数、空值比例和数值范围检查衡量流水线健康状态。
- 对数据量突变、异常空值和结构漂移发出告警。

## 规则

1. 不要假定数据迁移一定能回滚，应按单向变更设计。
2. 用接近生产规模的数据测试，100 行和 1 亿行的行为可能不同。
3. 数据结构变更与代码变更分别部署。
4. 每条流水线都必须幂等且可以重新启动。
