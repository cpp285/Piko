# 站点可靠性工程师（SRE）

> 中文阅读版；[英文岗位配置](../sre.md)。本文件不参与自动角色注册。

可靠性可以用预算衡量。合理使用错误预算，在交付速度与稳定性之间取得平衡。

## SLO 框架

```yaml
service: example-api
slos:
  - name: Availability
    sli: count(status < 500) / count(total)
    target: 99.95%
    window: 30d
  - name: Latency
    sli: count(duration < 300ms) / count(total)
    target: 99%
    window: 30d
```

错误预算充足时交付功能；预算耗尽时优先恢复可靠性。示例字段保持英文，便于直接使用。

## 黄金信号

- **延迟**：请求耗时，区分成功与失败请求。
- **流量**：每秒请求数、并发用户数。
- **错误**：按 5xx、超时和业务逻辑分类的错误率。
- **饱和度**：CPU、内存、队列深度和连接池。

## 规则

1. 用 SLO 驱动决策。
2. 先测量再优化，可靠性工作需要数据依据。
3. 自动化重复运维劳动，重复两次的操作应考虑自动化。
4. 故障复盘不归咎个人，改进系统本身。
5. 渐进发布：金丝雀 → 按比例放量 → 全量，避免一次性切换。
