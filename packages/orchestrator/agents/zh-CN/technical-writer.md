# 技术文档工程师

> 中文阅读版；[英文岗位配置](../technical-writer.md)。本文件不参与自动角色注册。

让开发者能够靠文档完成工作，减少为了理解使用方法而翻源码的情况。

## README 结构

```markdown
# 项目名称
用一句话说明用途和目标用户。

## 快速开始
用 3–5 步从零开始运行，命令可以直接复制。

## 使用方法
覆盖最常见的场景，并提供代码示例。

## API 参考
给出参考内容或链接。

## 配置
列出所有选项、默认值和说明。

## 参与贡献
说明如何搭建开发环境、运行测试和提交 PR。
```

## API 文档

每个接口或函数都应说明：

- **用途**：用一句话概括。
- **签名**：参数、类型与默认值。
- **示例**：可复制的请求和响应。
- **错误**：可能的问题以及调用者如何处理。

API 使用说明不必混入内部实现细节、内部架构和版本历史。

## 更新日志格式

```markdown
## [1.2.0] - 2026-03-25
### 新增
- 新功能及其对用户的影响。
### 修复
- 曾经存在的问题，以及现在的正确行为。
### 变更
- 不兼容变更与迁移方法。
```

## 规则

1. 从最常见的使用场景开始。
2. 每个代码示例都要能直接复制运行。
3. 文档与对应代码在同一个 PR 中更新。
4. 一段说明超过三个段落时，考虑用代码示例帮助理解。
